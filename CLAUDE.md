# DymoEnergy Backend Development Guide

## Quick Start

```bash
# Terminal 1: Run backend
cd H:\SolarShop\DymoEnergy
dotnet run --project src/DymoEnergy.HttpApi.Host
# → API running on http://localhost:5000/api

# Terminal 2: Run admin portal (Angular)
cd H:\SolarShop\DymoEnergy\angular
npm install
npm start
# → Admin UI on http://localhost:4200
```

## Architecture at a Glance

**Layered ABP Structure** (inside `src/`):
- `DymoEnergy.Domain` — entities, business logic
- `DymoEnergy.Application` — services, app logic, DTOs mapping
- `DymoEnergy.Application.Contracts` — interfaces, DTOs (public API)
- `DymoEnergy.Domain.Shared` — enums, constants
- `DymoEnergy.EntityFrameworkCore` — EF Core, migrations, repositories
- `DymoEnergy.HttpApi` — API controllers, routing
- `DymoEnergy.HttpApi.Host` — entry point, middleware, appsettings

## Database Migrations

```bash
# Add new migration
dotnet ef migrations add AddMyFeature --startup-project src/DymoEnergy.HttpApi.Host

# Apply migrations
dotnet ef database update --startup-project src/DymoEnergy.HttpApi.Host

# Revert last migration
dotnet ef database update LastMigrationName --startup-project src/DymoEnergy.HttpApi.Host
```

## AppService Pattern (ABP Standard)

```csharp
// Service interface (in Application.Contracts)
public interface IMyFeatureAppService : IApplicationService {
  Task<MyFeatureDto> GetAsync(int id);
  Task<CreateUpdateMyFeatureDto> CreateAsync(CreateUpdateMyFeatureDto input);
}

// Service implementation (in Application)
public class MyFeatureAppService : ApplicationService, IMyFeatureAppService {
  private readonly IRepository<MyFeatureEntity> _repo;
  
  public async Task<MyFeatureDto> GetAsync(int id) {
    var entity = await _repo.GetAsync(id);
    return ObjectMapper.Map<MyFeatureEntity, MyFeatureDto>(entity);
  }
}

// Auto-registered via ABP dependency injection
// Called from API controller (auto-generated by ABP) or directly from frontend
```

## Do's & Don'ts

✅ **Do:**
- Use `IRepository<T>` for data access (ABP provides CRUD by default)
- Return DTOs from app services, not entities
- Use `ObjectMapper.Map<>()` for DTO conversion
- Leverage ABP built-in features (pagination, filtering, validation)
- Follow the domain-driven design (entities own business rules)

❌ **Don't:**
- Query entities directly in controllers (use app services)
- Modify entities without going through repositories
- Hardcode connection strings (use appsettings.json)
- Ignore migrations (always migrate after schema changes)

## Common Troubleshooting

| Issue | Solution |
|-------|----------|
| "Cannot resolve symbol IXxxAppService" | Run `dotnet build` to regenerate cache |
| "Cannot open database connection" | Check SQL Server is running, appsettings.json has correct connection string |
| "Migration not applied" | Run `dotnet ef database update --startup-project src/DymoEnergy.HttpApi.Host` |
| "CORS errors in frontend" | Check CORS middleware in Program.cs allows frontend origin |
